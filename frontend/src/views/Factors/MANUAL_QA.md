# J18 deterministic manual screenshot states

The frontend has no component-test runner. Use an authenticated session and mock the listed API responses at the browser/proxy boundary. Keep `FACTOR_FEATURE_ENABLED` enabled except in the disabled-state case. Capture one desktop (1440 px) and one mobile (390 px) screenshot for each numbered state; IDs and timestamps below should remain fixed so visual comparisons are deterministic.

1. Catalog — `catalog-page-1`: return 21 active definitions for `page=1&page_size=20`. Verify 20 rows, total 21, a second page, and that category/market/status/search are sent to the server. Open `ret_20d` version 1 with formula `builtin.ret_20d`, dependency `ret_1d`, checksum of 64 `a` characters, and integer parameter `window=20`; capture the table and open detail drawer.
2. Compute validation — `compute-configured`: return one active CN factor `ret_20d` with integer, boolean, choice, and object parameters. Enter symbols `600519` and `000001`, dates `2026-08-26` through `2026-08-28`, as-of `2026-08-28T16:00:00+08:00`, universe `cn-demo-20260828`, and source `bars-20260828-r1`. Verify the estimate is 6 observation cells and the payload preserves the snapshot ID, UTC as-of, version/parameters, source versions, adjustment, chunk size, and workers.
3. Durable progress — `compute-running-42`: accept compute with job `job-factor-001`, task `11111111-1111-4111-8111-111111111111`, and a 64-character `b` checksum; return task progress `0.42`, stage `compute_chunks`, message `已完成 42/100 个代码`, and job symbols `42/100`. Reload before capture. Verify both status endpoints are called, 42% is displayed, and polling stops after `succeeded`, `failed`, or `cancelled`.
4. Snapshot values — `snapshot-ready-values`: return ready snapshot ID of 64 `c` characters, trade date `2026-08-28`, as-of `2026-08-28T08:00:00Z`, `row_count=98`, `expected_row_count=100`, sources `daily_bars=bars-r1` and `financials=fin-r3`, and a 50-row value page with `total=1000`. Mark `000002` with `ret_20d=null` and quality `INSUFFICIENT_HISTORY`. Verify only 50 rows render, page 2 is server-requested, abnormal symbols contains `000002`, and CSV contains only the current page.
5. Failure and disabled — `snapshot-failed` and `feature-disabled`: return failed snapshot error `SOURCE_VERSION_MISSING / bars-r0 unavailable`; capture its error summary. Separately return HTTP 404 detail `{code: "FACTOR_FEATURE_DISABLED"}` and capture the explicit disabled alert replacing the table.
6. Ownership/authentication — `factor-auth-redirect`: visit each `/factors/*` URL without a valid token and capture the resulting `/login` page. Cross-user API rejection remains covered by the J17 backend integration tests.
