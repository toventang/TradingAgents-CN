## 1. 业务目标

用户选择一个已发布策略，创建“自动模拟活动”Campaign。系统从活动激活后的第一个合法选股时点开始记录候选，按策略和资金规则自动产生模拟订单，持续监控持仓、止盈止损、策略退出和账户风险，直到到期或用户停止。活动结束后输出确定性绩效；每笔平仓后跟踪反事实价格路径，识别亏损和可能的“卖飞”，由AI基于结构化证据生成原因解释和参数改进建议。

目标是评估策略，不是承诺最终盈利。文档中的“测试最终盈利”实现为：

- 活动具有明确的start_at和end_at，或用户手动停止。
- 系统保存从起始资金到结束权益的完整净值。
- 未平仓持仓在报告中按end_at最后有效价估值；默认不强制卖出。
- 报告明确区分已实现盈亏、未实现盈亏、费用和基准收益。
- 系统不得把仍运行的活动描述为“最终”结果。

## 2. 前置重构：统一模拟经纪领域

现有app/routers/paper.py把账户、行情、市场识别、手续费、持仓和成交全部放在路由中。本功能实现前必须提取：

- SymbolNormalizer：输入任意旧代码，输出market、symbol、currency。
- MarketCalendarService：交易日、时段、下一合法成交点。
- MarketRuleService：手数、T+1、涨跌停、费用和规则版本。
- PriceSnapshotService：返回price、quote_time、source、quality、latency。
- PaperAccountService：账户、组合子账户、现金预留。
- PaperOrderService：订单状态、幂等和取消。
- PaperExecutionService：成交校验、费用、原子账本。
- PaperPositionService：lot、可卖数量、成本和估值。
- PaperPerformanceService：净值和绩效。

这些服务必须同时被手动模拟交易、自动活动和回测的对应适配器复用。API路由不得继续直接更新多个集合。

## 3. 模拟组合隔离

### 3.1 PaperPortfolio

一个用户仍有按币种的总模拟账户，但每个自动活动使用独立portfolio_id，避免多策略资金、持仓和归因混在一起。

字段：

- portfolio_id。
- user_id。
- name。
- type：manual、automation。
- market、currency。
- status：active、frozen、closed。
- initial_cash。
- cash、reserved_cash。
- realized_pnl、fees_total。
- campaign_id：automation时必填。
- account_version：乐观锁。
- created_at、updated_at、closed_at。

迁移：

- 为每个现有用户创建一个type=manual的default portfolio。
- 旧paper_positions/orders/trades补portfolio_id。
- 迁移脚本以user_id+manual_default为幂等键。
- 旧API未传portfolio_id时使用manual default，保持页面兼容。

### 3.2 资金规则

- Campaign创建时从模拟总账户为portfolio分配虚拟初始资金，不发生真实货币兑换。
- 同一币种下各portfolio资金之和不得超过账户该币种初始额度与已实现余额规则。
- 第一版禁止多个Campaign共享同一portfolio。
- Campaign结束后portfolio默认冻结，保留审计；用户可显式归档，不物理删除账本。
- 重置手动模拟账户不得静默删除自动活动；需分别确认。

## 4. Campaign模型与状态机

### 4.1 状态

draft → validating → ready → active  
active → pausing → paused → active  
active/paused → stopping → completed  
draft/ready → cancelled  
validating/active/stopping → failed

说明：

- draft：可编辑。
- validating：校验策略、数据、Skill、市场和资金。
- ready：等待start_at。
- active：允许生成信号和订单。
- paused：不产生新入场；按pause_policy决定是否继续止损/退出监控，默认继续。
- stopping：不产生新入场，处理待退出和结算。
- completed：结束时间、最终估值和报告已生成。
- failed：不可恢复错误；已有持仓必须冻结并提示用户处理，禁止消失。

### 4.2 Campaign字段

| 字段 | 说明 |
|---|---|
| campaign_id | UUID |
| user_id | 所有者 |
| name/description | 名称说明 |
| strategy_version_id | 冻结的发布策略版本 |
| analysis_profile_version_id | 可空；归因和解释使用 |
| market/currency | 单市场单币种 |
| portfolio_id | 独立模拟组合 |
| status/status_reason | 状态 |
| start_at/end_at | 开始和预期结束；end_at必须晚于start |
| schedule | 信号频率和交易时点 |
| initial_cash | 初始资金 |
| allocation | 仓位和候选分配规则 |
| risk_policy | 止盈、止损、组合风险 |
| execution_policy | 成交、滑点、费用、订单有效期 |
| pause_policy | paused时是否继续退出 |
| review_policy | 卖飞观察窗口、归因频率、Skill |
| learning_policy | 是否生成建议、最小样本、人工审核 |
| input_versions | 因子、Skill、市场规则和数据版本 |
| last_cycle_at/next_cycle_at | 调度 |
| version | 乐观锁 |
| created_at/activated_at/completed_at/updated_at | 生命周期 |

active后不可修改strategy_version_id、market、initial_cash、成交模型和已发生交易的规则。风险阈值调整必须创建campaign_config_revision，记录生效时间；不得回写历史。

## 5. 创建与激活

### 5.1 创建请求

必填：

- name。
- strategy_version_id。
- start_at、end_at或duration_trade_days。
- initial_cash。
- risk_policy。
- execution_policy。

可选：

- analysis_profile_version_id。
- max_candidates_per_cycle。
- max_new_positions_per_cycle。
- dry_run_before_activation，默认true。
- notification_preferences。

### 5.2 激活校验

1. 策略必须published，且用户有权运行。
2. Campaign市场必须与策略一致。
3. 因子和Skill版本可用。
4. start_at不得早于当前时间；允许最多5分钟时钟误差，但不得回填历史信号。
5. 初始资金满足市场最小交易。
6. max_positions、单股和行业上限一致。
7. 必须至少配置一种退出：策略退出、止损、时间退出三者之一；系统模板默认全部具备。
8. 止损百分比0.5%..50%，止盈0.5%..500%，追踪止损0.5%..50%。
9. 数据源和worker健康。
10. dry-run在最近一个有效快照生成候选和订单计划，但不写订单。
11. 用户确认风险免责声明。

校验失败保持draft，返回字段级errors和warnings。

### 5.3 “从选股当时开始”

- 系统只记录activated_at之后产生的信号。
- 第一条signal的observed_at必须≥activated_at。
- 日线收盘策略若在收盘前激活，从当日收盘后生成信号并在下一合法时点成交。
- 日线策略若在收盘确认后激活，不追溯使用当天已过去的执行机会；从下一次计划信号开始。
- 允许盘中策略时，必须使用fresh实时快照；信号价和成交价分别记录，不得把活动开始前的历史低价作为买入价。
- 每条候选保存selection_price、selection_quote_time和selection_snapshot_id，用于以后衡量从选股时点开始的表现。

## 6. 自动运行周期

### 6.1 SignalCycle顺序

1. CampaignScheduler选出next_cycle_at已到的active活动。
2. 获取分布式锁campaign_id+cycle_time。
3. 验证市场时段、数据源和Campaign版本。
4. 固定universe_snapshot。
5. 获取或创建factor_snapshot。
6. 执行发布策略，生成完整排名和reason_codes。
7. 排除已有持仓、待买订单、冷却期、黑名单、stale/invalid股票。
8. 先评估所有持仓退出。
9. 计算可用现金和目标权重。
10. 生成退出订单，再生成入场/调仓订单。
11. PaperOrderService幂等落单。
12. ExecutionService在合法成交点处理。
13. 更新持仓风险阈值、Campaign净值和统计。
14. 发送必要通知。
15. 写cycle结果并设置next_cycle_at。

每个cycle保存输入checksum；相同Campaign和cycle_time重试不得重复下单。

### 6.2 候选快照

automation_candidates字段：

- candidate_id。
- campaign_id、cycle_id。
- strategy_version_id。
- market、symbol、stock_name。
- selected_at、selection_price、quote_time。
- rank、score、factor_contributions。
- reason_codes。
- factor_snapshot_id、universe_snapshot_id。
- data_quality。
- eligibility：eligible、rejected、deferred。
- rejection_reasons。
- planned_weight、planned_notional、planned_quantity。
- order_id，可空。

必须保存全部进入top候选范围的股票，包括因资金/风控未买入者，这些未成交候选是机会成本和选股质量分析所必需。

### 6.3 数量和资金分配

确定性步骤：

1. target_equity = portfolio当前权益。
2. investable = target_equity×(1-min_cash_ratio)-当前持仓目标市值-待买预留。
3. 根据仓位模型得到目标权重。
4. 应用单股、行业和最大持仓数上限。
5. planned_notional=min(目标缺口, 可用资金)。
6. 按市场手数向下取整quantity。
7. 加上预估费用后再次校验现金。
8. 数量为0则candidate标记rejected:min_lot_or_cash。

不得为“充分利用资金”突破任何上限。

## 7. 订单、成交和持仓

### 7.1 自动订单

paper_orders新增：

- order_id。
- portfolio_id、campaign_id、cycle_id、candidate_id、signal_id。
- idempotency_key。
- origin：manual、automation。
- side、order_type。
- requested_qty、filled_qty、remaining_qty。
- signal_price、limit_price、stop_price。
- status：pending、accepted、partially_filled、filled、cancelled、expired、rejected。
- reject_reason。
- execution_policy_version。
- created_at、accepted_at、filled_at、expired_at。

任何状态变化写paper_order_events。

### 7.2 持仓lot

为准确处理T+1、部分卖出和归因，新增paper_position_lots：

- lot_id。
- portfolio_id、campaign_id。
- symbol、market、currency。
- entry_order_id、entry_trade_id、candidate_id。
- quantity、remaining_qty、available_from。
- entry_price、entry_fees、entry_at。
- initial_stop、initial_take_profit。
- current_stop、current_take_profit。
- highest_price_since_entry、lowest_price_since_entry。
- strategy_context_snapshot。
- status：open、closed。

paper_positions保留聚合展示，由lot账本派生；禁止只维护平均成本而丢失lot。

### 7.3 原子成交

一次fill必须原子完成：

1. 校验订单仍可成交且remaining_qty足够。
2. 校验fresh价格、市场规则和成交量。
3. 校验现金或available_qty。
4. 写trade。
5. 更新order。
6. 更新现金和费用。
7. 创建/减少lot。
8. 更新聚合position。
9. 写ledger_entry。

若Mongo事务不可用，使用唯一trade_id、账户version和补偿校验；任何中间失败不得重复扣款。

### 7.4 账本守恒

paper_ledger_entries采用复式意义的事件记录：

- entry_id、portfolio_id、trade_id。
- entry_type：cash_debit、cash_credit、fee、realized_pnl、dividend、adjustment。
- currency、amount。
- balance_after。
- created_at。

每天和每次成交后运行reconciliation：

- cash变化=所有ledger累计。
- position数量=所有open lot remaining_qty之和。
- order filled_qty=其trade数量之和。
- portfolio权益=现金+持仓市值。

不一致时冻结该portfolio的自动下单并产生critical系统预警。

## 8. 风险与退出

### 8.1 RiskPolicy

- fixed_stop_loss_pct。
- fixed_take_profit_pct。
- trailing_stop_pct或trailing_atr_multiple。
- atr_stop_multiple。
- max_holding_trade_days。
- strategy_exit_enabled。
- max_position_weight。
- max_industry_weight。
- max_portfolio_drawdown_pct。
- daily_loss_limit_pct。
- consecutive_loss_pause_count。
- cooldown_trade_days_after_exit。
- stop_action：full_exit；第一版不做部分止损。
- take_profit_action：full_exit或partial，partial需给比例。
- conflict_policy：conservative为默认。

规则优先级：

1. 账本异常/管理员冻结。
2. 组合最大回撤或日亏损停机。
3. 强制退市/不可交易状态。
4. 止损。
5. 追踪止损。
6. 止盈。
7. 策略退出。
8. 时间退出。
9. 调仓减仓。

高优先级产生订单后，低优先级只记录also_triggered，不重复下单。

### 8.2 盘中触发

- 有可靠盘中high/low/last时可评估价格止损止盈。
- 只有日线数据时沿用回测同K冲突规则。
- stale快照不执行价格退出；产生风险预警并在下一fresh快照重试。
- A股T+1导致止损不可卖时，创建blocked_exit订单并持续重试，报告必须计入T+1额外损失。
- 跌停无法卖出同理记录blocked_by_limit_down。

### 8.3 组合停机

触发max_portfolio_drawdown或daily_loss_limit：

- Campaign进入paused_by_risk。
- 取消未成交买单。
- 默认继续退出规则。
- 通知用户原因、权益、阈值和持仓。
- 只有用户显式确认才能resume；不得由AI自动恢复。

## 9. 活动净值与完成

### 9.1 每日快照

automation_equity_daily：

- campaign_id、portfolio_id、trade_date。
- cash、reserved_cash、market_value、equity。
- realized_pnl、unrealized_pnl、fees。
- daily_return、cumulative_return、drawdown。
- benchmark_equity、excess_return。
- positions_count、turnover。
- data_quality、valued_at。

unique(campaign_id, trade_date)。

### 9.2 完成规则

到达end_at：

1. 停止新入场。
2. 按completion_policy决定：
   - mark_to_market：默认，保留持仓并以最后fresh价格估值。
   - liquidate：创建退出订单，等待最多配置的交易日；无法成交则按市值保留并标记。
3. 等待未决订单完成/过期。
4. 运行reconciliation。
5. 生成确定性绩效。
6. 为已闭合交易创建归因任务；未完成反事实窗口的卖飞分析标记pending。
7. Campaign先进入completed_pending_review，窗口完成后进入completed_reviewed；对外可统称completed并展示子状态。

### 9.3 绩效

除回测指标外必须提供：

- 从selection_price到entry_price的执行延迟损益。
- 候选组合收益、实际持仓收益和两者差异。
- 因资金不足、手数、风控、重复持仓而错过的候选表现。
- 自动退出与假设一直持有到Campaign结束的差异。
- 按策略信号批次、行业、持有期、退出原因、原因码分组。
- blocked_exit造成的额外损失。
- 数据/系统故障影响时长。

## 10. 亏损归因

### 10.1 归因边界

代码先计算事实，AI后解释。AI不得修改交易价格、收益、最大有利/不利变动或原因阈值。

每笔闭合lot生成TradeReviewInput：

- 入场候选排名和全部因子贡献。
- 入场/退出策略版本和规则快照。
- selection、signal、entry、exit时间与价格。
- 费用、滑点、延迟。
- 持有期间OHLC路径。
- MAE：最大不利变动。
- MFE：最大有利变动。
- 市场/行业同期收益。
- 新闻和事件时间线。
- 风险触发、blocked状态。
- 数据质量和系统异常。
- 对照候选及未入选边界样本。

### 10.2 标准原因码

一级原因必须从以下枚举选择，可多选并给权重，权重和=1：

#### SELECTION

- OVERVALUED_AT_ENTRY
- WEAK_FINANCIAL_QUALITY
- GROWTH_REVERSAL
- FALSE_MOMENTUM
- SENTIMENT_FALSE_POSITIVE
- FACTOR_CROWDING
- LOW_LIQUIDITY_SELECTED
- INDUSTRY_SELECTION_ERROR

#### TIMING

- ENTERED_TOO_EARLY
- ENTERED_TOO_LATE
- EXITED_TOO_EARLY
- EXITED_TOO_LATE
- SIGNAL_LAG

#### RISK

- STOP_TOO_TIGHT
- STOP_TOO_WIDE
- TAKE_PROFIT_TOO_LOW
- POSITION_TOO_LARGE
- CONCENTRATION_TOO_HIGH
- HOLDING_PERIOD_TOO_LONG

#### EXECUTION

- SLIPPAGE_HIGH
- FEES_HIGH
- PARTIAL_FILL_IMPACT
- T1_BLOCKED_EXIT
- LIMIT_DOWN_BLOCKED_EXIT
- STALE_DATA_DELAY

#### EXTERNAL

- MARKET_REGIME_CHANGE
- INDUSTRY_SHOCK
- COMPANY_EVENT
- MACRO_EVENT
- UNPREDICTABLE_GAP

#### DATA_MODEL

- DATA_MISSING
- DATA_STALE
- FACTOR_CALCULATION_ERROR
- POINT_IN_TIME_BIAS_RISK
- MODEL_REASONING_UNSUPPORTED

### 10.3 确定性候选原因

AttributionEngine先根据规则生成候选：

- entry后1..3日快速下跌、之后恢复：ENTERED_TOO_EARLY候选。
- selection到entry上涨超过阈值且随后回撤：ENTERED_TOO_LATE或SLIPPAGE_HIGH。
- 因T+1/跌停延迟退出：对应EXECUTION原因，损失按可执行首时点对照计算。
- 止损后N日内价格显著恢复且没有基本面失效：STOP_TOO_TIGHT候选。
- MFE达到止盈目标但实际未退出：EXITED_TOO_LATE或执行异常。
- 实际持仓权重超过策略目标：POSITION_TOO_LARGE。
- 负面事件published_at后出现：COMPANY_EVENT，不得倒因为选股时已知。

AI Skill trade_loss_attribution对候选、证据和反证进行解释，输出：

- primary_causes：code、weight、confidence、evidence_refs、counter_evidence。
- controllability：controllable、partially_controllable、uncontrollable。
- summary。
- recommended_review，不直接改参数。

无足够证据时必须输出INSUFFICIENT_EVIDENCE警告，不得编造新闻或财务事实。

## 11. “卖飞”与反事实分析

### 11.1 定义

卖飞不是“卖出后任何上涨”。一个闭合lot满足以下条件才标记possible_missed_upside：

1. 在exit后的observation_window内存在fresh、可交易价格。
2. post_exit_mfe = max(high_after_exit)/exit_fill_price - 1。
3. post_exit_mfe ≥ missed_upside_threshold，默认10%。
4. 相对基准超额上涨≥excess_threshold，默认5%。
5. 不是因退市、数据修正或错误价格产生。

severity：

- minor：10%..20%。
- material：20%..40%。
- major：≥40%。

阈值可配置但必须版本化。

### 11.2 观察窗口

- 默认20个交易日，同时支持5/10/20/60日。
- Campaign结束时窗口未满，review_status=observing。
- 每个窗口保存MFE、MAE、期末收益、基准收益和可交易性。
- 不得用窗口内最高价作为“本来一定能卖到”的收益；它仅是最大有利变动。

### 11.3 退出质量对照

至少计算：

- actual_exit_return：实际lot净收益。
- hold_to_window_end_return：持有至窗口末收盘的假设收益。
- best_possible_mfe：仅诊断。
- strategy_reentry_return：若策略之后重新入场。
- alternative_stop_return：只对预先定义的参数网格计算。
- exit_efficiency = 已实现收益 / 退出前MFE，分母≤0时为空。

反事实必须扣除相同费用和合法成交约束，不能按不可成交的最高价计算。

### 11.4 卖飞原因

- TAKE_PROFIT_TOO_LOW。
- TRAILING_STOP_TOO_TIGHT。
- STOP_TOO_TIGHT。
- EXIT_SIGNAL_TOO_SENSITIVE。
- REENTRY_BLOCKED_BY_COOLDOWN。
- PARTIAL_EXIT_ALLOCATION_ERROR。
- VALID_RISK_EXIT：虽然后续上涨，但当时退出符合风险规则，非错误。
- UNPREDICTABLE_POST_EXIT_EVENT：退出后新事件推动，不应归咎原规则。

AI必须区分“事后结果不好”和“当时决策不合理”。存在退出时未知的新事件时，应优先VALID_RISK_EXIT或UNPREDICTABLE_POST_EXIT_EVENT。

## 12. 受控学习

### 12.1 学习对象

只允许建议以下白名单参数：

- 因子组合权重。
- 入场排名阈值。
- 固定/ATR/追踪止损。
- 止盈阈值。
- 最大持有期。
- 冷却期。
- 最大持仓数、单股和行业权重。
- 调仓频率。

禁止建议或自动改变：

- 用户初始资金。
- 权限、API Key或数据源凭证。
- 历史记录。
- 账本和实际成交。
- 任意代码、工具白名单或安全预算。
- 已发布策略版本。

### 12.2 最小证据

默认满足全部条件才生成可操作建议：

- 至少30笔闭合交易。
- 至少覆盖60个交易日。
- 不能全部来自同一股票。
- 数据质量valid/partial比例≥95%。
- 无未解决账本异常。
- 建议参数在策略声明的tunable范围。
- 有训练/验证时间切分。

样本不足时只生成“观察”，不生成参数修改建议。

### 12.3 LearningProposal

- proposal_id、campaign_id、user_id。
- source_strategy_version_id。
- status：draft、needs_review、approved_for_backtest、rejected、validated、applied。
- sample_summary。
- attribution_distribution。
- proposed_changes：path、old_value、new_value、reason。
- evidence_refs。
- expected_effect：假设，不是承诺。
- risks、tradeoffs。
- validation_plan。
- llm_model_ref、skill_version_id、prompt_checksum。
- reviewer_id、reviewed_at、review_comment。
- validation_backtest_ids。
- target_strategy_version_id，可空。
- created_at、updated_at。

### 12.4 建议流程

1. 聚合结构化归因。
2. 检查最小证据和数据偏差。
3. Learning Skill生成白名单内建议和验证计划。
4. Validator拒绝越界、互相冲突或过拟合风险高的建议。
5. 用户审阅；可逐项接受/拒绝。
6. 接受只会创建“候选策略草稿”，不会修改原发布版本。
7. 自动启动或由用户启动样本外回测。
8. 满足验证门槛后proposal=validated。
9. 用户再次确认，才可发布新策略版本并用于新Campaign。
10. 旧Campaign继续使用原版本，不中途变更。

### 12.5 验证门槛

文档不规定“必须提高收益”这一单指标。默认比较：

- 样本外总收益和超额收益。
- 最大回撤。
- Sharpe/Sortino。
- 交易数和换手。
- 尾部损失。
- 参数邻域稳定性。

建议版本若收益增加但回撤、费用或样本外稳定性显著恶化，必须标记tradeoff，不得自动推荐为优胜。

## 15. 前端

### 15.1 活动创建向导

1. 选择发布策略并显示最新回测，不强制把回测好视为可用。
2. 选择开始、时长、初始资金和市场。
3. 设置候选数、仓位和现金。
4. 设置止损、止盈、追踪、时间退出和组合停机。
5. 设置成交、滑点和费用。
6. 设置归因窗口和学习开关。
7. 运行校验/dry-run。
8. 展示完整规则摘要、数据延迟、风险免责声明并确认激活。

### 15.2 活动详情

- 状态、下一周期、数据健康和风险停机。
- 权益、基准、回撤、费用。
- 当前持仓、lot、止损/止盈距离和可卖数量。
- 最新候选：已买、拒绝、延期及原因。
- 订单时间线：信号、提交、阻塞、部分成交、成交。
- 活动事件和通知。
- 暂停、恢复、停止；危险操作二次确认。

### 15.3 复盘

- 每笔交易selection→entry→exit→观察窗口的价格图。
- 因子贡献、事件时间线、MFE/MAE。
- 亏损原因码、证据、反证和可控性。
- 卖飞不能只显示最高涨幅；同时显示窗口末收益和基准。
- 聚合视图按原因、行业、信号批次、退出规则和持有期分组。

### 15.4 学习中心

- 显示样本是否满足门槛。
- 建议逐项diff、证据、预期影响和副作用。
- 用户可以接受部分建议。
- 显示验证回测和样本外结果。
- “创建策略草稿”与“发布”必须是两个独立动作。
- 禁止出现“AI已自动优化并应用”而没有审核记录。

## 16. 通知

产生站内通知：

- Campaign激活/暂停/恢复/完成/失败。
- 新入场和退出成交。
- 止损/止盈触发及被T+1/跌停阻塞。
- 组合回撤停机。
- 数据stale、worker失败、账本不一致。
- 归因完成。
- 卖飞观察达到material/major。
- 学习建议待审核或验证完成。

普通周期成功、普通净值变化不得发送通知，避免噪音。

## 17. 测试

### 17.1 状态和权限

- 每个合法/非法状态转换。
- active后不可修改冻结字段。
- 用户A不能读取或操作用户B Campaign/portfolio/review。
- 版本冲突返回409。

### 17.2 交易

- 活动激活前信号不被使用。
- 日线信号下一合法时点成交。
- 手数、费用、T+1、涨跌停、停牌。
- 部分成交、过期、幂等重试。
- 两个worker同cycle只生成一组订单。
- 手动portfolio和automation portfolio隔离。
- 成交中间失败后账本可恢复且不重复扣款。

### 17.3 风险

- 止损、止盈、追踪、ATR、时间和策略退出。
- 多规则同日只按最高优先级下一个订单。
- 同K冲突保守处理。
- stale不成交。
- 组合回撤取消买单并暂停。
- T+1/跌停阻塞损失被记录。

### 17.4 归因

- MAE/MFE手算。
- 事件发生时间晚于退出，不可归为入场可知原因。
- 卖飞阈值、基准超额和多个窗口。
- 最高价只作为MFE，不作为可实现收益。
- VALID_RISK_EXIT和真正EXITED_TOO_EARLY可区分。
- 数据不足输出INSUFFICIENT_EVIDENCE。

### 17.5 学习

- 少于30笔只产生观察。
- 非白名单参数被拒绝。
- 接受建议只创建草稿。
- 原发布版本和运行中Campaign不变。
- 样本外验证失败仍可查看，但不能标validated。
- 全流程保留Skill版本、模型引用和证据。

### 17.6 端到端验收场景

固定20只A股、120个交易日fixture：

1. 创建并发布一个动量策略。
2. 创建Campaign，start_at在第21日收盘前。
3. 第21日收盘产生候选，第22日开盘成交。
4. 一只股票止盈、一只止损、一只因T+1阻塞、一只因资金不足未买。
5. 运行至end_at并生成净值、交易、候选机会成本。
6. 继续推进20日反事实窗口。
7. 至少生成一个亏损归因和一个possible_missed_upside。
8. 聚合样本不足时学习中心明确不允许参数建议。
9. 扩充fixture到30笔后生成建议，人工接受，创建新策略草稿。
10. 样本外回测通过后仍需人工发布。

最终核对：

- 账本逐日守恒。
- 所有交易可追溯到候选、信号、策略、因子和数据时间。
- 所有AI结论可追溯到结构化事实和Skill版本。
- 没有跨用户数据、重复订单、历史回填或无审核自我修改。
