## 1. 功能二：扩充分析策略

### 1.1 “策略”的两个层次

为避免把提示词、选股条件和交易规则混为一谈，系统必须拆分：

1. 分析配置 AnalysisProfile：决定启用哪些分析师、Skill、数据窗口、研究深度、风险偏好和输出关注点；它产生研究报告，不直接下单。
2. 量化策略 StrategyDefinition：用确定性规则定义股票池、信号、排序、调仓、仓位、买卖和风险控制；它可用于筛选、回测和自动模拟交易。

一个量化策略可以关联一个分析配置，用AI解释候选和事后结果，但AI输出不得覆盖确定性交易规则。

### 1.2 策略生命周期与版本

#### Strategy

- strategy_id：稳定ID。
- user_id：私有策略所有者；系统模板使用system。
- name、description、tags。
- kind：screening、ranking、portfolio。
- visibility：private、shared_readonly、system。
- current_draft_version_id。
- latest_published_version_id。
- created_at、updated_at、archived_at。

#### StrategyVersion

- strategy_version_id。
- strategy_id。
- version：从1递增。
- status：draft、validating、published、deprecated。
- market：CN/HK/US。
- definition：完整结构化定义。
- analysis_profile_version_id：可空。
- factor_dependencies：发布时冻结的因子版本。
- skill_dependencies：发布时冻结的Skill版本。
- checksum。
- validation_result。
- created_by、created_at、published_at。
- change_summary、parent_version_id。

发布版本不可修改；修改必须复制为新draft。回测、信号和自动交易必须引用明确的strategy_version_id，禁止只引用strategy_id。

### 1.3 策略定义DSL

definition固定包含以下对象：

| 区块 | 必填 | 内容 |
|---|---:|---|
| universe | 是 | 股票池、上市天数、ST/退市/停牌、行业、市值过滤 |
| data | 是 | 频率、复权、最少历史、允许的数据质量 |
| features | 是 | 因子和组合因子引用 |
| entry | 是 | 入场条件树或排名规则 |
| exit | 是 | 出场条件树、止盈、止损、时间退出 |
| rebalance | 是 | daily/weekly/monthly及具体交易日 |
| portfolio | 是 | 持仓数、权重、单股/行业上限、现金下限 |
| execution | 是 | 信号时点、成交时点、价格、滑点、费用模型 |
| risk | 是 | 最大回撤停机、波动目标、止盈止损、冷却期 |
| benchmark | 是 | 基准代码和市场 |
| analysis | 否 | AnalysisProfile和解释要求 |

#### 条件树

只允许以下节点：

- all：全部子条件为真。
- any：任一子条件为真。
- not：对子条件取反。
- compare：左值、操作符、右值。
- cross_up/cross_down：时间序列交叉。
- rank：横截面百分位或前N。
- changed：最近N期变化超过阈值。

左值和右值只能是factor、constant或另一个factor引用。操作符白名单为gt、gte、lt、lte、eq、neq、between。数值、周期和参数必须经过Pydantic校验。

#### 排名与组合

- 支持按一个或多个因子排序。
- 多因子排序先分别标准化再加权。
- tie_breaker必须显式指定，默认symbol升序，保证可复现。
- top_n和top_percent只能二选一。
- 排名必须在过滤后的同一universe_snapshot上完成。

#### 仓位模型

第一版支持：

- equal_weight：等权。
- score_weight：正分数归一化；负分数默认不做多。
- inverse_volatility：按20/60日波动倒数分配。
- fixed_weight：显式symbol权重，仅适用于静态组合。

共同限制：

- max_positions范围1..200。
- max_position_weight范围0.01..1。
- max_industry_weight范围0.05..1。
- min_cash_ratio范围0..0.9。
- 分配后低于最小交易单位或最低名义金额的订单舍弃，并重新分配一次。
- 第一版仅支持多头现货，不支持融资、做空、期权、期货和跨币种自动兑换。

系统必须交付以下14个可查看、可克隆但不可直接修改的模板：

| momentum_20_60 | 20/60日动量高、流动性合格 | MA20下穿MA60、追踪止损 | 周度 |
| low_volatility | 低波、低beta、低回撤 | 波动排名恶化 | 月度 |
| high_dividend_quality | 股息率高、盈利和现金流稳定 | 分红下降、现金流恶化 | 月度 |
| mean_reversion_rsi | RSI超卖且长期趋势未破坏 | RSI恢复、止损、时间退出 | 日度 |

每个模板必须附带：

- 明确公式、默认参数、适用市场和不适用场景。
- 最少历史长度和依赖因子。
- 基准、成本和滑点默认值。
- 参数敏感性范围，不允许只给一个“最佳参数”。
- 风险提示；不得描述为保证盈利。

### 1.5 AnalysisProfile

字段：

- profile_id、version、user_id、name、status。
- selected_analysts：market、fundamentals、news、social的非空子集。
- research_depth：快速/基础/标准/深度/全面。
- quick_model_ref、deep_model_ref；引用配置而不是复制密钥。
- risk_preference：conservative、balanced、aggressive。
- investment_horizon：intraday不可选、short、medium、long。
- enabled_skill_versions。
- factor_context：最多50个要注入报告的因子；必须先生成结构化摘要，禁止把全量时序塞入prompt。
- strategy_context：strategy_version_id。
- debate_rounds、risk_debate_rounds，受系统上限约束。
- output_schema_version。
- disclaimer_profile。

现有analysis请求继续支持selected_analysts和research_depth；未传profile_id时按旧参数构造临时Profile。传profile_id时禁止同时传冲突参数。

### 1.6 策略校验

发布前执行：

1. JSON Schema/Pydantic结构校验。
2. factor_id、version、参数和市场支持检查。
3. 条件树深度≤10、节点数≤200。
4. 检查未来引用、非法成交时点和点时财务要求。
5. 检查入场条件是否可能永远为假、退出是否为空。
6. 检查仓位上限相互冲突。
7. 检查依赖Skill已发布且权限足够。
8. 使用固定小样本执行dry-run，确认每个阶段有结果。
9. 输出error和warning；存在error不得发布，warning需用户确认。

### 1.7 策略数据集合和索引

- strategies：unique(strategy_id)，(user_id, updated_at desc)。
- strategy_versions：unique(strategy_id, version)，unique(strategy_version_id)，(user_id, status)。
- analysis_profiles：unique(profile_id, version)，(user_id, status)。
- strategy_signals：unique(strategy_version_id, market, symbol, signal_date, signal_type)，并保存factor_snapshot_id、score、rank、reason_codes和输入贡献。
- universe_snapshots：不可变股票池；unique(universe_snapshot_id)，(market, trade_date)。

### 1.9 策略前端

- 策略中心：模板、我的草稿、已发布、已归档。
- 策略向导：股票池 → 因子 → 入场 → 退出 → 仓位 → 执行 → 风控 → 校验。
- 高级模式展示结构化树，不提供任意代码编辑器。
- 策略详情：版本差异、依赖、最近信号、回测、关联自动模拟活动。
- AnalysisProfile设置：分析师、模型、Skill、深度、风险偏好、关注因子。
- 发布确认必须展示数据需求、估算成本、风险规则和不可变版本号。

### 1.10 策略验收

- 14个模板全部可以克隆、校验、发布、生成信号并启动回测。
- 同一strategy_version、factor_snapshot和universe_snapshot重复运行产生相同信号。
- 发布版本无法PUT修改。
- 用户A无法读取、克隆未共享或运行用户B的策略。
- 非法因子、依赖环、空退出规则、超限条件树、未来成交规则均被拒绝。
- 旧筛选页面可继续运行；旧条件可一键转换为screening策略草稿。

## 2. 功能三：回测系统

### 2.1 回测目标和范围

第一版是日频、多股票、多头现货、事件驱动回测，支持CN/HK/US市场但单个回测只使用一个基础货币和一个市场。它必须复用发布策略、因子快照和模拟交易的市场规则，不另写一套互相矛盾的成交逻辑。

第一版不支持：

- 分钟/Tick级别。
- 融资融券、卖空、期权、期货。
- 跨市场统一资金池和自动汇率换算。
- 实盘券商连接。
- 用LLM即时改变历史交易规则。

### 2.2 防未来数据规则

1. trade_date收盘数据生成的信号，最早在next_trade_date的开盘或用户指定的下一个合法成交点执行。
2. 财务数据从publish_date后的首个交易日才可见。
3. 新闻和社交数据必须使用published_at/ingested_at中较晚者，并且只能进入其后的信号窗口。
4. 股票池成分必须使用当时可知的上市、退市、ST和指数成分，禁止只使用今天仍上市的股票。
5. 复权因子只能用于构造连续收益；成交价、涨跌停、手续费和现金必须按当时未复权价格处理。
6. 任何输入缺少point-in-time能力时，结果必须标记bias_warning，默认阻止自动学习使用。

### 2.3 回测请求

必填：

- strategy_version_id。
- market。
- start_date、end_date。
- initial_cash，必须>0。
- benchmark。
- execution_model_id。

可选：

- parameter_overrides：只允许策略声明为tunable的字段，不生成新策略版本。
- universe_override：仅研究用途，结果标记。
- seed：需要随机滑点时必填，默认固定。
- save_daily_positions：默认true。
- notes。

系统校验：

- 起止日期和至少60个有效交易日。
- 策略、Skill、因子版本存在且用户有权访问。
- 历史数据覆盖率。
- 初始资金足以满足至少一笔最小交易。
- 同一用户并发回测上限默认2，全局上限可配置。

### 2.4 每交易日事件顺序

严格按以下顺序执行：

1. 加载交易日和上一日收盘后的可见数据。
2. 应用公司行为：现金分红、拆并股、送转；记录现金和数量变化。
3. 释放到期结算或T+1可卖数量。
4. 处理上一周期生成的待成交订单。
5. 校验停牌、涨跌停、成交量和价格。
6. 按执行模型成交、部分成交或保持/取消。
7. 扣除佣金、税费、滑点和其他费用。
8. 更新现金、持仓成本、已实现盈亏和订单。
9. 使用当日可见数据计算因子和策略信号。
10. 先执行退出决策，再生成入场/调仓订单，订单进入下一个合法成交点。
11. 收盘估值并记录净值、持仓、暴露、回撤和数据质量。
12. 写审计事件并检查取消请求。

同一天同一股票同时触发止损与策略买入时，退出优先，且冷却期内禁止重新买入。

### 2.5 市场与成交规则

#### A股

- 买入数量按100股整数手；卖出允许清仓零股，其他卖出按市场规则。
- T+1：当日买入不可当日卖出。
- 停牌不成交。
- 涨停时买单默认不成交，跌停时卖单默认不成交；若使用历史成交量近似模型，可配置概率/参与率，但默认严格不成交。
- 主板、创业板、科创板、北交所和特殊处理股票的涨跌幅限制由日期化market_rule_version确定。
- 佣金、最低佣金、印花税按成交日期版本计算。

#### 港股

- 股票手数从市场规则或证券元数据读取。
- T+0。
- 支持交易费、交易征费和结算费。

#### 美股

- 第一版只允许整数股；T+0卖出逻辑按模拟规则。
- SEC等卖出费用按日期化规则。

#### 执行模型

内置：

- next_open：下一交易日开盘。
- next_vwap_proxy：下一交易日OHLC/成交量估算VWAP，仅用于研究。
- next_close：下一交易日收盘。

滑点：

- fixed_bps：成交方向不利移动N个基点。
- volume_impact：base_bps + impact_coefficient×sqrt(order_notional/daily_amount)。
- 参与率默认不得超过当日成交量10%；超过则部分成交并保留剩余订单最多3日。

成交价必须裁剪到当日low..high内；若裁剪发生，记录execution_warning。

### 2.6 止盈、止损和退出语义

所有价格触发按OHLC可观察性处理：

- 固定止损：从持仓平均成本向下百分比。
- 固定止盈：从平均成本向上百分比。
- ATR止损：entry_price - k×entry_atr。
- 追踪止损：持仓后最高可观察价格回撤百分比或ATR倍数。
- 时间退出：持有N个交易日。
- 信号退出：策略条件转为真。
- 最大组合回撤停机：停止新买入，可配置是否清仓。

若同一根日K同时触及止盈和止损而无法知道先后：

- conservative：按对策略更不利的价格处理，默认。
- optimistic：研究用途，结果标记。
- open_path：根据开盘相对位置的确定性启发式，结果标记。

任何报告必须展示采用的同K冲突规则。

### 2.7 账本和结果

#### backtest_runs

保存run_id、task_id、user_id、strategy_version_id、请求、输入版本、状态、bias_warnings、summary、错误和时间。

#### backtest_orders

order_id、run_id、signal_id、symbol、side、requested_qty、remaining_qty、order_type、created_trade_date、expire_date、status、reject_reason。

#### backtest_trades

trade_id、order_id、run_id、symbol、side、quantity、raw_price、slippage、fill_price、notional、fees明细、trade_date。

#### backtest_positions_daily

run_id、trade_date、symbol、quantity、available_qty、avg_cost、close、market_value、unrealized_pnl、weight、holding_days。

#### backtest_equity_daily

run_id、trade_date、cash、market_value、equity、daily_return、cumulative_return、drawdown、benchmark_equity、turnover、gross/net_exposure。

#### backtest_events

记录信号、订单、拒绝、部分成交、公司行为、风控、数据缺失、取消和异常。

大规模日持仓可以按run_id和月份分块存储；不得把全部交易和净值嵌入backtest_runs。

索引至少包括：

- unique(run_id)
- (user_id, created_at desc)
- (run_id, trade_date)
- unique(trade_id)
- (run_id, symbol, trade_date)

### 2.8 绩效指标

必须由确定性代码计算并给出公式口径：

- 初始/最终权益、总收益、年化收益CAGR。
- 日收益均值、年化波动。
- Sharpe：无风险利率可配置，默认0并展示。
- Sortino和下行波动。
- 最大回撤、回撤起止和恢复日期。
- Calmar。
- 相对基准收益、beta、alpha、信息比率、跟踪误差。
- 胜率、亏损率、盈亏比、profit factor。
- 单笔平均/中位收益、最大单笔盈利/亏损。
- 持有期平均/中位数。
- 换手率、总费用、滑点成本、费用占毛收益比例。
- 曝险、现金比例、最大单股/行业集中度。
- 交易数、拒单数、部分成交数。
- 月度/年度收益表。
- 退出原因分布。

闭合交易采用FIFO lot归因；同时保留持仓平均成本供账户展示。指标少于30个交易日或交易数不足10时显示样本不足警告。

### 2.9 参数研究

第一版提供：

- 单参数扫描。
- 最多3个参数的网格搜索。
- 滚动样本：train/validation/test时间切分。
- walk-forward：用户设置训练窗和验证窗。

限制：

- 组合数默认≤100，系统上限500。
- 每个组合生成独立子运行，共享只读输入缓存。
- 最优结果必须同时展示测试外表现和参数稳定性。
- 禁止仅按全样本最高收益自动发布参数。

| GET /api/backtests/{run_id}/trades | 交易分页 |
| GET /api/backtests/{run_id}/positions | 指定日期或区间持仓 |
| GET /api/backtests/{run_id}/events | 事件分页 |
| GET /api/backtests/{run_id}/metrics | 全部指标和口径 |
| POST /api/backtests/compare | 比较最多10个有权限的run |
| POST /api/backtests/parameter-search | 创建参数研究父任务 |
| GET /api/backtests/{run_id}/export | 导出CSV/JSON；大文件异步 |

### 2.11 回测前端

- 创建页：选择已发布策略、区间、资金、基准、成交、成本和参数。
- 运行页：阶段、确定性进度、取消、数据质量和警告。
- 结果总览：净值/回撤、指标卡、月度热力图、基准比较。
- 交易复盘：买卖点、订单/成交、费用、退出原因。
- 持仓分析：行业、个股、现金、暴露和集中度。
- 参数实验室：热力图、样本内/外、稳定性，不用单一“最优”误导用户。
- 比较页：相同口径提示，不同市场/区间/成本的结果默认禁止直接排名。

### 2.12 回测测试与验收

必须有手算fixture：

1. 单股上涨、无费用，核对收益。
2. 手续费和最低佣金。
3. A股T+1阻止当日卖出。
4. 涨停买不进、跌停卖不出。
5. 停牌。
6. 分红和拆股。
7. 同K止盈止损冲突。
8. 部分成交和订单过期。
9. 财务发布日期防未来。
10. 退市股票仍在历史股票池，防幸存者偏差。
11. 取消后不再产生交易。
12. 固定seed重复运行完全一致。

验收要求：

- 所有账本满足：期末权益=现金+持仓市值，且每日日终误差在货币最小单位内。
- 每笔成交前后现金和数量守恒。
- 报告中明确成本、滑点、成交时点、复权、同K冲突和偏差警告。
- 至少使用一个内置策略跑通CN完整流程，并与独立手算抽样核对。
