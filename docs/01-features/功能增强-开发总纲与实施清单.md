## 2. 总体交付边界

### 2.1 必须交付

- 171个首批因子及版本化注册、批量并行计算、快照和有效性分析。
- 组合因子DSL和可视化配置。
- AnalysisProfile和量化策略双层模型。

- 固定/ATR/追踪止损、止盈、时间和策略退出。

- 全部后端API、Vue页面、菜单、权限、迁移、索引、日志、指标和测试。

### 2.2 第一版明确不做

- 实盘券商下单。
- 分钟/Tick高频回测。
- 融资、做空、期货、期权。
- 跨币种自动兑换。
- 用户上传并执行任意代码。
- AI自行修改并发布策略。
- 短信、邮件、企业微信等外部通知渠道；接口可预留。

任何新增范围必须另建需求，不得悄悄混入实现。

## 4. API统一约定

### 4.1 响应

同步成功：

    {
      "success": true,
      "data": {},
      "request_id": "uuid"
    }

异步创建返回HTTP 202：

    {
      "success": true,
      "data": {
        "resource_id": "领域ID",
        "task_id": "任务ID",
        "status": "queued"
      },
      "request_id": "uuid"
    }

失败：

    {
      "success": false,
      "error": {
        "code": "STABLE_MACHINE_CODE",
        "message": "用户可理解文本",
        "field_errors": [],
        "retryable": false,
        "details": {}
      },
      "request_id": "uuid"
    }

要求：

- details必须脱敏。
- 400校验、401未登录、403越权、404不存在、409状态/版本冲突、422语义校验、429配额、503依赖不可用。
- 不能为了兼容把失败包装成HTTP 200 success=false。
- 日期时间输出带时区。
- 分页统一page、page_size、total、items；page_size默认20，上限200。

### 4.2 所有权

每个私有资源查询步骤：

1. 从JWT依赖得到真实user_id。
2. 查询条件同时包含资源ID和user_id。
3. 不向无权用户泄露资源是否存在；统一404或按系统安全约定。
4. system模板只读。
5. 后台任务从持久任务读取user_id，不信任payload中重复字段。

### 4.3 幂等

以下操作必须支持Idempotency-Key：

- 创建因子计算。
- 创建回测。
- 激活Campaign。
- Campaign周期下单。
- 生成归因。
- 创建学习策略草稿。

服务端保存request_hash；同键不同请求返回409 IDEMPOTENCY_KEY_REUSED。

## 5. 配置与功能开关

所有新能力默认关闭，逐阶段开启：

| 配置 | 默认 | 说明 |
|---|---:|---|
| FEATURE_FACTOR_ENGINE | false | 因子API和页面 |
| FEATURE_STRATEGY_ENGINE | false | 新策略 |
| FEATURE_BACKTEST | false | 回测 |
| FEATURE_ALERTS | false | 用户预警 |
| FEATURE_RUNTIME_SKILLS | false | Skill执行 |
| FEATURE_AUTOMATION | false | 自动模拟 |
| FEATURE_AI_ATTRIBUTION | false | AI归因；确定性归因仍可运行 |
| FEATURE_LEARNING_PROPOSALS | false | 学习建议 |
| DOMAIN_WORKER_ENABLED | false | 通用worker |

运行参数：

- FACTOR_MAX_WORKERS=8。
- FACTOR_SYMBOL_CHUNK_SIZE=100。
- DOMAIN_TASK_MAX_ATTEMPTS=3。
- DOMAIN_TASK_LEASE_SECONDS=300。
- BACKTEST_USER_CONCURRENCY=2。
- ALERT_MIN_FREQUENCY_SECONDS=30。
- ALERT_DEFAULT_FREQUENCY_SECONDS=60。
- ALERT_STALE_QUOTE_SECONDS按市场分别配置。
- AUTOMATION_USER_ACTIVE_CAMPAIGNS默认5。
- LEARNING_MIN_CLOSED_TRADES=30。

配置必须进入现有Settings/ConfigProvider体系，不得只读取某一种来源而破坏部署兼容。敏感配置不进入前端。

## 6. 数据库迁移规则

### 6.1 迁移框架

新增app/migrations或项目统一迁移目录，每个迁移包含：

- migration_id和description。
- up函数。
- verify函数。
- batch_size和断点cursor。
- dry_run。
- 幂等标识。
- 处理数量、跳过数量和错误。
- 不可逆步骤的备份/恢复说明。

不得在普通API请求中隐式执行全量迁移。

### 6.2 迁移顺序

1. 创建domain_tasks和事件索引。
2. 建立规范symbol/market适配，不立即删除旧字段。
3. 创建因子/策略/回测集合。
4. 创建alert集合并迁移favorites阈值。
5. 创建Skill集合和系统内置manifest。
6. 创建paper_portfolios、lot、ledger和order events。
7. 给旧paper数据补manual portfolio_id。
8. 创建automation、review和learning集合。
9. 后台核对新旧模拟账户余额和持仓。
10. 稳定一个版本后才考虑弃用旧字段，当前范围不物理删除。

### 6.3 索引门禁

每个repository首次使用前确认索引存在；生产启动不得每次阻塞式重建大索引。迁移verify必须检查：

- unique索引没有重复数据。
- 所有用户查询有user_id前缀索引。
- 所有周期扫描有status+next_time索引。
- 大历史查询有resource_id+date索引。
- TTL只用于可再生缓存/租约，不得删除账本、交易、回测或审计。

## 7. 分阶段实施清单

每个步骤都必须按“模型 → repository → service → router → frontend API/type → 页面 → 单元测试 → 集成测试 → 文档”的顺序闭环。允许一个PR只实现后端基础设施，但其功能开关必须保持关闭且不得声称用户功能完成。

### Phase 0：安全和基础缺陷

#### P0-01 真实用户身份

- 修复WebSocket通知硬编码admin。
- 任务进度按所有者推送。
- 增加跨用户HTTP和WebSocket测试。
- 检查OperationLogMiddleware真实用户映射。

退出条件：任意两名测试用户的通知、任务、规则完全隔离。

#### P0-02 股票标识统一

- 实现SymbolNormalizer。
- 新模型统一market+symbol。
- analysis主路径只使用规范symbol。
- 旧code/stock_code输入适配和弃用告警。

退出条件：CN/HK/US代表代码在分析、筛选、模拟交易中得到同一规范结果。

#### P0-03 通用任务

- domain_tasks模型、repository、状态机、lease、heartbeat、取消和事件。
- 改造/适配Redis QueueService，使其payload包含task_type。
- domain_worker按handler registry分发。
- worker崩溃恢复测试。

退出条件：API重启和worker崩溃不会静默丢任务。

#### P0-04 模拟交易领域拆分

- 从paper router提取市场规则、账户、订单、成交、持仓。
- 不改变现有前端行为。
- 为现有API补全手算测试。

退出条件：paper router不直接跨集合写账，旧模拟交易回归通过。

- 扩大用户。
- 保留快速关闭，不删除数据。

## 8. 测试门禁

### 8.1 测试层次

- unit：纯函数、状态机、公式、validator，不访问网络。
- repository：临时MongoDB/Redis，索引、幂等和并发。
- integration：FastAPI鉴权、API、worker和数据持久化。
- contract：前端TypeScript类型和后端OpenAPI契约。
- E2E：Vue操作到后端任务和结果。
- performance：显式运行，不作为每次快速测试。
- migration：空库、旧数据、重复执行和中断恢复。

### 8.2 必须阻止合并的失败

- 任一用户隔离测试失败。
- 任一账本守恒测试失败。
- 任一防未来数据测试失败。
- OpenAPI和前端契约漂移。
- 新代码静态导入错误。
- 新集合缺少规定索引。
- 因子结果含未序列化NaN/Infinity。
- AI输出未通过schema仍进入下游。
- 功能开关关闭时仍启动自动任务。

### 8.3 外部数据

- 单元/集成测试全部使用固定fixture。
- 在线数据源测试标记integration/external并默认跳过。
- fixture记录来源字段、生成日期和是否合成。
- 测试不得把真实API Key写入仓库或日志。

## 9. 性能和资源预算

必须通过配置限制：

- 单用户同时因子任务、回测、Campaign数量。
- 最大股票池、日期范围、因子数。
- 单回测最大交易日和参数组合。
- 预警规则总数、最小频率和每日事件数。
- Skill的LLM/tool/token预算。
- API响应最大数组和导出大小。

长任务内存峰值、CPU时间、Mongo批量大小和Redis队列长度写入可观测指标。达到限制返回明确429/422，不允许服务进程OOM。

## 10. 安全清单

- JWT真实身份，不使用admin占位。
- Access/Refresh token类型校验属于上线前安全基线。
- CORS按部署域名限制。
- API Key只在后端密钥存储和模型客户端中使用。
- 日志移除token/key前缀、完整请求头和敏感配置。
- Skill和策略禁止任意代码。
- 导出文件校验所有权并使用短期下载。
- WebSocket不记录token查询参数。
- 重要操作写operation log：策略发布、Campaign激活/停止、规则启停、Skill授权、学习应用。
- 不允许自动模拟功能连接真实券商。

## 11. 需求覆盖矩阵

| 原始需求 | 后端 | 数据 | 前端 | 关键验收 |
|---|---|---|---|---|
| 上百因子并行计算 | FactorRegistry、Engine、Analysis | definitions/jobs/snapshots/values/results | 目录、计算、实验室、组合 | 171因子、并行、可复现、无未来 |

## 12. AI每步执行模板

AI开始一个编号任务前必须输出/记录：

1. 本任务ID和目标。
2. 依赖是否已完成。
3. 将读取和修改的文件。
4. 数据迁移和兼容风险。
5. 测试计划。
6. 功能开关状态。

完成后必须提供：

1. 实际变更文件。
2. API/数据模型差异。
3. 执行的测试命令和结果。
4. 未执行测试及原因。
5. 性能或安全影响。
6. 需求条目覆盖证据。
7. 遗留问题，不能隐藏在TODO中。

禁止：

- 在同一批次顺手重构无关模块。
- 删除用户现有改动。
- 用mock结果证明生产数据链已打通。
- 将未实现项标为完成。
- 没有测试就进入下一Phase。

## 13. 最终Definition of Done

六项功能只有同时满足以下条件才算整体完成：

- 四个分卷的所有“必须”和验收项已逐条勾选并附测试证据。
- 所有新路由进入FastAPI主应用并出现在OpenAPI。
- 所有新页面进入Vue路由、鉴权和侧边栏。
- 新旧字段兼容迁移完成，旧页面回归通过。
- 功能开关关闭时无后台副作用；开启后能恢复任务。
- 多用户隔离、多实例幂等、数据库索引通过。
- 因子和回测没有未来数据泄漏。
- 自动模拟账本逐日守恒。
- stale/invalid数据不会触发自动交易。
- AI只解释结构化事实，不能直接改账本和发布策略。
- 学习建议经过人工审核和样本外验证。
- 后端测试、前端类型检查、生产构建和关键E2E全部通过。
- 安全日志审查确认不泄露JWT和API Key。
- 部署、迁移、回滚、运维和用户操作文档完成。
- 至少使用固定fixture完整演示：因子 → 策略 → 回测 → 预警 → Campaign → 退出 → 归因 → 学习草稿。

任何一项不满足，状态只能是“部分完成”。
