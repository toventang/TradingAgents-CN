## 0. 文档定位与执行规则

本文件不是概念方案，也不是仅供讨论的架构设计，而是“实现合同”。开发者必须能够仅依赖本文件和当前源码完成任务拆分、编码、迁移、测试和验收。

原始需求包含六项：

1. 上百因子的并行计算、分析和组合分析。
2. 扩充分析策略。
3. 增加回测。
4. 增加实时监控与预警。
5. 增加 AI Skill 设置。
6. 智能选股后自动进入模拟交易，设置止盈止损，追踪最终收益，自动分析亏损和卖飞原因并形成可审核的学习建议。

### 0.1 规范词

- “必须”：不可省略；缺失即验收失败。
- “应当”：除非有明确、记录在案的技术原因，否则必须实现。
- “可以”：可选增强，不阻塞当前阶段。
- “完成”：代码、数据库索引、API、前端、权限、日志、测试、迁移和文档全部闭环，不等于“核心函数已写”。
- “实时”：本项目第一阶段定义为交易时段内按配置频率轮询最新行情并在一个检测周期内产生事件，必须保证微秒级（不能超过1毫秒）行情。
- “学习”：只能生成版本化、可解释、可回滚、需要审核后才能应用的参数建议；禁止模型自行修改源码、提示词、账户资金或已发布策略。

### 0.2 不允许的实现捷径

- 不得在 FastAPI 请求进程内用无持久化的 BackgroundTasks 承载因子全市场计算、回测、监控或自动交易任务。
- 不得用 LLM 直接计算收益、技术指标、成交、手续费或回测指标；确定性数值必须由代码计算，LLM只能解释。
- 不得在回测中使用未来数据、当前数据库中的“最新财务值”替代历史时点值，或在当日收盘价产生信号后仍按同一收盘价成交。
- 不得把用户 ID 写死为 admin，不得跨用户读取策略、预警、回测或模拟账户。
- 不得把 API Key、JWT、完整提示词中的敏感变量、完整持仓请求记录到普通日志。
- 不得通过任意 Python 表达式、eval、exec、动态 import 或前端传入的代码执行策略和因子。
- 不得只做前端页面而返回假数据，也不得只做后端接口而不接入主导航和真实页面。
- 不得覆盖现有模拟交易集合；必须通过向后兼容迁移扩展。

### 1.2 必须先处理的基线缺陷

以下问题是功能开发的前置任务，不修复不得启用实时预警或自动模拟交易：

1. WebSocket通知端点从令牌解析真实 user_id，删除硬编码 admin。
2. 任务进度推送只能发送给任务所有者，禁止全局广播用户任务。
3. 统一股票标识为 symbol + market，兼容输入 stock_code/code，但新集合不得继续扩散旧字段。
4. 主分析链路统一使用规范化后的 symbol，不能任务创建时规范化、执行时再次读取可能为空的 stock_code。
5. 把 paper router 中账户、手续费、成交和持仓逻辑迁移至 service；路由只做校验、鉴权和响应转换。
6. 建立通用持久任务模型；API进程重启后 queued/running 任务必须可恢复、重试或明确失败。
7. 全部新集合必须带 user_id 或 visibility=system；所有查询必须显式包含所有权条件。
8. 修复 screening router 重复注册 GET /fields 的冲突，只保留一个稳定响应契约。

### 2.2 统一处理链

数据同步 → 数据质量检查 → 因子计算 → 因子快照 → 策略信号 → 回测或实时候选 → 自动模拟交易 → 估值与退出监控 → 绩效/反事实归因 → 学习建议。

每个结果必须可追溯到：

- 数据截止时间 as_of。
- 交易日 trade_date。
- 因子定义版本 factor_version。
- 策略版本 strategy_version_id。
- Skill版本 skill_version_id。
- 任务 ID task_id。
- 原始信号快照 signal_snapshot_id。
- 数据源和数据质量状态。

### 2.3 全局技术约束

#### 时间

- 数据库存储统一为带时区 UTC datetime。
- API输出 ISO 8601，必须带 Z 或偏移。
- 市场交易日判断使用市场日历，A股默认 Asia/Shanghai；不得用服务器本地日期替代。
- 日线信号的 as_of 必须是该交易日收盘后时间；下一可交易时点成交。

#### 数值

- 价格、金额、手续费和净值写库前使用 Decimal 语义按市场精度舍入；不得依靠二进制 float 作为账务最终值。
- 因子中间计算可用 float64，但必须把 NaN、正负无穷转换成 null，并记录质量原因。
- 百分比字段统一存小数，例如 5% 存 0.05；仅展示层乘100。旧字段若以百分数存储，适配层必须显式转换。

#### 幂等与并发

- 写任务必须接受 Idempotency-Key；相同用户、端点、请求体摘要和键返回同一任务。
- 任务领取采用原子状态转换 queued → running；worker必须有 heartbeat 和 lease_expires_at。
- 自动交易事件使用 campaign_id + rule_id + symbol + market + evaluation_window 作为幂等键。
- 同一账户资金/持仓更新必须在 MongoDB事务可用时使用事务；不可用时采用账户版本号 compare-and-set，并在失败时重试。

#### 数据质量

每个数据批次和因子结果必须携带 quality_status：

- valid：数据完整且通过校验。
- partial：部分字段缺失，但允许计算。
- stale：超过市场和频率定义的新鲜度。
- suspended：股票停牌。
- invalid：复权、价格、成交量或财务时点不合法。
- unavailable：数据源均失败。

策略默认只可使用 valid/partial；partial是否可参与由策略声明。stale/invalid/unavailable不得触发自动买入。

## 3. 通用持久任务系统

六项功能共享任务基础设施，避免每个模块再实现一套状态和进度。

### 3.1 任务状态机

queued → running → succeeded  
queued → cancelled  
running → cancelling → cancelled  
running → retry_wait → queued  
running/retry_wait → failed  
服务重启后 lease 过期的 running → retry_wait 或 failed。

### 3.2 domain_tasks 集合

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| task_id | UUID字符串 | 是 | 外部稳定标识 |
| user_id | 字符串 | 是 | 所有者 |
| task_type | 枚举 | 是 | factor_compute、strategy_run、backtest、alert_eval、campaign_eval、attribution |
| status | 枚举 | 是 | 使用上述状态机 |
| priority | 整数 | 是 | 0普通、10交互、20系统紧急 |
| payload | 对象 | 是 | 已校验的任务参数 |
| progress | 0..1 | 是 | 确定性进度 |
| stage | 字符串 | 是 | 当前阶段代码 |
| message | 字符串 | 否 | 用户可见消息 |
| result_ref | 对象 | 否 | 结果集合与ID，禁止嵌入大结果 |
| attempt/max_attempts | 整数 | 是 | 默认0/3 |
| worker_id | 字符串 | 否 | 当前执行者 |
| heartbeat_at | datetime | 否 | 心跳 |
| lease_expires_at | datetime | 否 | 租约 |
| cancel_requested_at | datetime | 否 | 协作式取消 |
| error | 对象 | 否 | code、message、retryable、details脱敏 |
| created_at/started_at/finished_at/updated_at | datetime | 是/否 | 生命周期 |
| idempotency_key/request_hash | 字符串 | 否 | 幂等 |

索引：

- unique(task_id)
- unique(user_id, task_type, idempotency_key)，仅幂等键存在时生效
- (status, priority desc, created_at)
- (user_id, created_at desc)
- (lease_expires_at)，用于恢复僵尸任务

### 3.3 通用任务 API

- GET /api/tasks/{task_id}：所有者读取状态。
- POST /api/tasks/{task_id}/cancel：queued直接取消，running设置取消请求。
- GET /api/tasks?type=&status=&page=&page_size=：分页查询。
- GET /api/tasks/{task_id}/events：分页读取持久化进度事件；WebSocket断线后可补偿。

统一错误：

- TASK_NOT_FOUND
- TASK_FORBIDDEN
- TASK_NOT_CANCELLABLE
- TASK_QUEUE_UNAVAILABLE
- TASK_CONCURRENCY_LIMIT
- TASK_RETRY_EXHAUSTED

## 4. 功能一：上百因子并行计算与组合分析

### 4.1 用户目标

用户可以查看因子目录，选择市场、股票池、日期区间和因子集合，执行单股时序分析或全市场横截面计算；可以把多个因子做标准化、方向调整、行业/市值中性化、加权组合和分层分析，并将组合保存为策略输入。

### 4.2 因子定义模型

FactorDefinition必须包含：

| 字段 | 说明 |
|---|---|
| factor_id | 稳定、全局唯一、小写蛇形标识 |
| version | 整数；公式或缺失值语义变化必须升版 |
| name/display_name/description | 中英文名称和准确含义 |
| category | price、trend、momentum、volatility、liquidity、valuation、quality、growth、sentiment、event、cross_section、composite |
| frequency | daily；预留 intraday、quarterly |
| required_columns | 精确列名列表 |
| dependencies | 依赖的基础或派生因子 |
| params_schema/default_params | 参数类型、范围和默认值 |
| min_history | 最少历史条数 |
| formula_ref | 注册函数名，不允许动态代码 |
| direction | positive、negative、neutral；仅用于默认打分 |
| winsorize_default | none、mad、quantile |
| normalize_default | none、zscore、rank、robust_zscore |
| missing_policy | drop、neutral、industry_median、zero，仅允许白名单 |
| supported_markets | CN/HK/US |
| point_in_time_required | 是否要求时点财务数据 |
| status | draft、active、deprecated |
| checksum | 定义内容摘要 |

因子注册采用静态 Python registry + 数据库只读镜像。数据库不得存储可执行源码。启动时对 factor_id、依赖环、参数范围、输出列冲突做校验。

### 4.4 因子计算行为

#### 输入规范

- 日线列统一为 market、symbol、trade_date、open、high、low、close、pre_close、volume、amount、adj_factor。
- 先按 market+symbol+trade_date 去重，再按日期升序。
- 复权价格由 adj 参数决定；价格因子默认 qfq，回测成交使用当时可交易的未复权价格并用复权因子处理公司行为。
- 财务因子按 publish_date 生效，而不是 report_period；发布日期缺失的数据不得参与点时回测。
- 横截面计算必须固定 universe_snapshot_id，避免计算过程中股票池变化。

#### 依赖图

- FactorRegistry构建有向无环图。
- 基础列 → 公共中间量 → 单因子 → 横截面变换 → 组合因子。
- 公共中间量如 returns、true_range、rolling_mean只计算一次。
- 发现环、未知依赖、同名输出或非法参数时，任务在开始计算前失败。

#### 并行策略

- 并行单元默认为 symbol chunk，而不是每个因子启动一个线程，避免重复复制DataFrame。
- 纯CPU计算使用有上限的进程池；数据库读取和写入使用异步批量I/O。
- 默认 chunk_size=100只股票、worker数=min(CPU核数-1, 8)，允许配置但必须设置1..16上限。
- 每个chunk写独立临时批次；所有chunk成功后原子发布 snapshot。部分失败不得把不完整快照标记为ready。
- 单股票多因子计算复用同一数据窗口；不得每个因子重新访问数据源。
- 任务进度按完成股票数/总股票数计算，不得用定时模拟。

#### 缺失值和异常值

1. 原始数据缺失先标记，不前向填充价格和成交量。
2. 财务值只可在发布日期后向前延用到下一次披露。
3. 默认横截面去极值使用中位数±5×MAD。
4. 标准化在每个trade_date、market内进行；可选行业内标准化。
5. 有效样本小于20只时不生成横截面zscore。
6. 因子值超出定义域时置null并写 quality_reason。

### 4.5 组合因子DSL

组合定义只能使用结构化JSON，支持：

- factor：引用 factor_id + version + params。
- transform：identity、negate、log1p_abs、winsorize_mad、winsorize_quantile、zscore、robust_zscore、percentile_rank。
- neutralize：none、industry、market_cap、industry_and_market_cap。
- arithmetic：weighted_sum、mean、geometric_mean；第一版禁止任意公式。
- missing：drop_symbol、renormalize_weights、neutral_score。
- filter：因子有效性、市值、行业、上市天数、ST/退市/停牌过滤。

加权和规则：

- 权重可为任意有限数，保存前统一归一化为绝对值之和=1。
- factor.direction为negative时，只有用户选择auto_direction=true才自动反向。
- 缺失时renormalize_weights只能在剩余绝对权重达到原权重60%以上时使用，否则该股票结果为空。
- 输出同时保存 raw_score、normalized_score、rank、coverage_ratio、contributions。

### 4.6 因子分析

必须提供：

- 单因子时序图、分布、缺失率、极值率、覆盖股票数。
- 横截面Rank IC、Pearson IC、IC均值、标准差、ICIR、正IC比例。
- 按未来1/5/10/20日收益评估；标签必须通过日期偏移生成，禁止泄漏。
- 分位数组合Q1..Q5或Q10收益、单调性、多空收益、换手率。
- 因子相关矩阵和高相关告警，默认绝对相关>0.85。
- 行业暴露、市值相关、beta暴露。
- 因子衰减曲线。
- 所有分析显示样本区间、股票池、交易成本是否包含、有效样本数。

### 4.7 数据集合

#### factor_definitions

保存定义镜像、版本、checksum、status；unique(factor_id, version)。

#### factor_jobs

保存计算请求、universe、日期、因子版本列表、task_id、统计和错误摘要。

#### factor_snapshots

| 关键字段 | 说明 |
|---|---|
| snapshot_id | 发布后的不可变快照 |
| market/trade_date/as_of | 时间边界 |
| universe_snapshot_id | 股票池 |
| factor_set_checksum | 因子集合摘要 |
| status | building、ready、failed、superseded |
| row_count/factor_count | 完整性校验 |
| source_versions | 行情/财务批次 |

#### factor_values

一条记录可按 symbol+trade_date 存多个因子值，避免每个值单文档。字段包括snapshot_id、market、symbol、trade_date、values、quality、created_at。

索引：

- unique(snapshot_id, market, symbol, trade_date)
- (market, trade_date, snapshot_id)
- (symbol, trade_date desc)

#### factor_analysis_results

保存IC、分层收益、相关性、暴露和数据质量摘要，大数组可拆分子文档。

### 4.10 因子验收

- 171个目录因子全部可发现；每个有单元测试和定义版本。
- 1000只股票×5年日线×100因子在配置的基准环境中可完成，任务不阻塞API；性能基线写入测试报告。

- 因子分析标签偏移测试证明不存在未来函数。
- 旧screening字段ma20、rsi14、kdj、MACD结果在声明的兼容误差内保持一致。
